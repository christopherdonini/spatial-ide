# DRAFT 4 — Landing page redesign brief (site/, GitHub Pages)

*Fable, 2026-09-14. Low-priority governance node; no product code. The page's job: one screen of
truth, phone-first, readable in ten seconds. Content rules unchanged: no perf number without a
docs/08 measurement; `done` only with evidence. Single static HTML + one CSS file, generated by the
existing script; no framework; < 100 KB; progressive enhancement (all content without JS).*

## Bugs first (fix before any styling)

1. **Health from the wrong place.** "CI on main: unknown" and "Open PRs: offline" — the health line
   runs `gh` on the dev machine. CI status, open-PR count/age, and latest release must come from
   the **GitHub API at Pages build time** (Actions has a token). Machine facts (disk, stray
   processes) stay machine-side, written by the custodian's flush commit, shown on their own line
   with their own timestamp — never mixed with build-time facts.
2. **"Shipped since your last visit — loading…"** — the JS never ran or never resolved. Store
   last-visit in `localStorage` in a try/catch; fallback without JS: "shipped in the last 7 days."
3. **Labels glued to titles** ("…ADR acceptancesruling (20 min)"): render need-type and minutes as
   a separate chip, never concatenated text.
4. **Node ids exposed** (`briefa-p3-p6`): the id is metadata — show on expand or as `title=`,
   never as the visible label.
5. **Dates.** The hero-slice nodes show 2026-09-13 because their evidence is the release; show
   *evidence date* labelled as such, or the landing date of the PR that built them. "Part O —
   sitting (0 min)" — a zero estimate renders as "unestimated", never 0.

## Information hierarchy (top to bottom)

1. **Status strip** — small pills: CI on main · drift checks · open PRs (count, oldest) · latest
   release (v0.1.0, date) · machine (disk free, stray processes, its timestamp). Green/amber/red by
   rule, never by taste; each pill links to its source.
2. **Current milestone banner** — one sentence in the user's-outcome voice ("Open an ordinary
   file, inspect, filter, colour, save, reopen, publish the intended result") with a stage bar:
   Brief A → B1 → B2 → B3 → Part O, each stage's status colour, the active stage highlighted.
3. **Waiting on you** — cards grouped by need type (click · sight · ruling · sitting), each with
   minutes, age, and **"unblocks N nodes"** (computed from `depends_on` — the single most useful
   number on the page: it tells the human which ten minutes matter most). Sort by unblocks
   desc, then age. Total minutes per group in the group header.
4. **Shipped since your last visit** — evidence-linked lines, newest first; the v0.1.0 release
   as one card with its four verbs, not four rows.
5. **The board** — lanes as swimlanes. Desktop: horizontal lanes, nodes as chips left (done) to
   right (ahead), dependency arrows as light SVG lines between chips. Mobile: lanes as
   collapsible sections, "after: …" rendered as a small linked chip. Lane order = the approved
   priorities. Empty lanes collapse to one line. "Ambition" lanes render dashed, labelled with
   their docs/07 phase, visually quieter than active lanes.

## Node chip

Title (no id) · status colour · need-type chip when blocked on human · evidence icon when done
(links to PR/ADR/log) · phase tag for unscheduled nodes. Expand (details/summary, no JS needed):
id, depends_on, gate, evidence, dates.

Status colours (one legend, top-right): done = green filled · in-progress = blue · ready = teal
· blocked-on-human = amber · blocked-on-deps = grey outline · unscheduled = dashed grey.

## Visual system

- System font stack; 16 px base; line-height 1.5; text columns max 72ch; the board full width.
- Light and dark via `prefers-color-scheme`; contrast ≥ 4.5:1 on every chip text.
- Space, not lines: 8-px grid, 24-px section gaps; no borders on cards, subtle background tint.
- One accent colour (the amber of "waiting on you") used for exactly one thing.
- Header: "Spatial IDE" + "plan" — not "custodian's plan"; a stranger may land here. Keep the
  repository and release links; remove the raw CI badge image in favour of the status pill.

## Accessibility and honesty

- Chips carry `aria-label` with status in words; the board is a real list under the hood.
- Keyboard: every chip focusable; expand on Enter.
- No animation; no external fonts or scripts; no perf numbers; every "done" carries its link.

## Acceptance

Render on a phone width (≤ 400 px) and a desktop width; the three bugs gone; a stranger can say
in ten seconds what shipped, what's current, and what the project is waiting on. Reviewer-gated;
the generator's tests updated for the new structure; `verify:plan` unchanged.
