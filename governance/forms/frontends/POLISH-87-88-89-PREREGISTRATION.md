## §2. Entry 87 — a refused per-tile mint is reported truthfully and retried, never silently discarded

**2.1 Hypothesis.** Per-tile filter admission leases `LeaseClass::Maintenance` (`engine/src/predicate.rs:118-122`), whose capacity is 1 (`engine/src/pool.rs:99`), while the shell issues up to `MAX_IN_FLIGHT_TILE_STREAMS = 3` (`frontends/shell/src/canvas/tileGridConstants.ts:40`) concurrent `viewport_query` calls; `acquire` refuses rather than waits (`pool.rs:262-275`). A lost lease is mapped to `FilterError::RejectedByBinder` (`predicate.rs:118-122`, its doc `:240-242`) → `skp.filter_rejected_by_binder` (`kernel/src/skp.rs:749-753`), and the shell's bare `catch` (`frontends/shell/src/streaming/tileViewportStreamManager.ts:663-669`) deletes the tile's state with no log, no trace, no status, no requeue. The tile stays in the cover, never resident: `isFillComplete()` stays false.

**2.2 Discriminator, FIRST (test 1).** One run with a log line at that `catch` naming `err.skpError.code` and its `fields` (`SkpCallError`, `frontends/shell/src/skp/client.ts:24-31`): the refusals must be `skp.filter_rejected_by_binder` whose `detail` names the *lease*, not DuckDB's binder (the `detail` text is minted at `predicate.rs:120`). A `detail` naming a real binder refusal, or another code, stops the engine half for an amendment; the shell half (2.3 (i)/(iii)) proceeds either way.

**2.3 The rule — BOTH sites, split on the docs/02 module boundary (the engine owns its pool; the kernel only maps typed errors).**
 (i) **Shell, unconditional (docs/01 principle 8).** The `catch` logs one `logSessionEvent` line per refusal — `tile-stream-mint-refused <tileKey>: <code> <fields>` — and the two epoch-abandon branches (`tileViewportStreamManager.ts:671-680`) log theirs. A typed refusal is never discarded unnamed again.
 (ii) **Engine, the honest fix (principle 8: the reported cause must be the cause) — on the human's word (entry 91 (a)).** Per-request predicate admission stops sharing the whole-file-pass budget: a third declared lease class for admission work, sized so the admissions the binding can present concurrently cannot collide (≥ `MAX_STREAM_CONNECTIONS`), with `MAX_PHYSICAL_CONNECTIONS` (`pool.rs:102`) re-derived and the new ceiling declared at its site with the quantity it bounds (ADR-010 rule 6, `ADR-010:70`).  (iii) **Shell, bounded requeue (principle 7, "never block the canvas" made honest).** On a code in a declared retryable set — initially `engine.connections_exhausted` alone, and until (ii) lands also `skp.filter_rejected_by_binder` when its `detail` names the lease — the tile returns to the queue as `queued` under its current epoch, so `drainQueueIfRoom` (`tileViewportStreamManager.ts:639-647`) retries it when a slot frees. Bounded: **at most one retry per drain per tile, and only while the tile is still in the current cover**; a tile that has left the view is dropped by the existing supersede path. Any other code keeps today's drop, now logged. No constant, ceiling, wording, enumeration or eviction change in the shell.

## §3. Entry 88 — the blink per notch: standing-until-settle, only as a declared labelled state

**3.1 What the blink is.** Each wheel notch is its own camera burst: the mid-gesture rule clears a standing id (`frontends/shell/src/canvas/pickResolution.ts:131-143`, D2) and the settle re-pick restores it after `HOVER_REPICK_SETTLE_MS` (`hoverRepickConstants.ts:34`). A standing *refusal* already does not blink (`pickResolution.ts:138-140`), so only the id case is felt.

**3.2 The rule, and the honest shape.** "The last readout stays displayed, not re-asserted, until the settle re-pick replaces or clears it" displays an id at a camera nothing has confirmed. Unlabelled, that is the hazard ADR-010 rule 5 names by name — *"staleness is signalled, never silently served"* (`ADR-010:68`) — and docs/01 principle 8. Therefore: **stale-and-unlabelled is refused here.** Two admissible shapes only: **(a)** the readout stands with a *visible declared distinction* (a dimmed/marked `.hover-readout` state whose text or class differs from a confirmed id) until the settle replaces or clears it — which **is** entry 75 (3)'s "unconfirmed state", said plainly, and is the human's to open; or **(b)** today's clear stands. This piece builds (a) **only on the human's ruling reopening entry 75 (3)** (entry 91 (b)); the wording of any new marking is the human's. Filed as **Amendment 6 to `HOVER-REPICK-PREREGISTRATION.md`** (amending D2 and D6's caller), never an edit of that file.

**3.3 K6 (i)–(v) under (a).** (i), (iii), (iv), (v) hold unchanged, provided the marked state is textually distinguishable so `hoverReadoutId` (`regression.mjs:1141-1144`) cannot read it as a confirmed id. **(ii) changes and is the only change:** "no readout is ever an id without a confirming trace" becomes "no **confirmed** readout is ever an id without a confirming trace since the mark; a marked stale readout is not a confirmed readout" — a K6 contract change, reviewer-gated, and block-on-sight 13 still applies (the replacement keeps a case whose correct answer is a *different* id or an absence). New unit cases in `pickResolution.test.ts` for the mid-gesture decision's third return (mark, don't clear), and one `WorkingCanvas.test.ts` case that the marked state is always replaced or cleared at settle.

**3.4 Declared.** Unchanged: the settle mechanism, D1/D3/D4/D5/D11, both constants, the emission choke point, the threshold. **Invalidators:** any stale readout displayed without a visible distinction; the human declining to reopen 75 (3) (the piece ends at §3.2 (b), nothing built). **Falsification:** a marked readout that outlives its settle; K6 (iv) no longer failing on a retained id.
