# 03 — UX

## Modes

- **Explorer** — view, search, share. Zero learning curve.
- **Analyst** — SQL, joins, linting, notebooks.
- **Developer** — API console, plugin development, protocol tools.

One **command palette** across everything: fuzzy search over datasets, operations, settings, docs, and features (principle 2).

## The action console

Every GUI action emits its API/SQL equivalent in a visible console (the Blender trick). Three payoffs: it teaches users the API gradually, it makes any session recordable into a notebook, and it feeds the AI training flywheel (04).

## Map as live query

SQL view ↔ visual query builder, round-tripping in both directions. Layers are live query results; upstream edits propagate through the DAG (02) and the map updates incrementally.

## Problems panel — spatial linting

Deterministic background checks surfaced like code diagnostics: invalid geometries, mixed CRS, duplicate vertices, suspicious unit results. Each with a quick fix. AI explains and proposes; deterministic checks decide (04).

## Layer inspection

Hover any layer → instant column stats and histograms (dataframe-profiler style). No dialog digging.

## Notebooks

Reactive and DAG-based — no hidden mutable state; stale cells are visibly stale; execution order is the graph, not the scroll order. The action console provides the raw material, but notebooks compile to the **Workflow IR** (13) with explicit inputs, parameters, and side-effect declarations — recording is the start, not the artifact. A cell can capture a map state; scrubbing through a notebook scrubs the map.

## Scenario branches

Branch project state like git branches for what-if planning; diff two branches visually. Built on lineage versioning (02).

## Style-as-code

A typed, diffable style DSL. The style editor is a GUI over the DSL, not a separate system. AI can write cartography because styles are code (04, 06).

## Sharing

One-click publish of a **static interactive bundle** — style + metadata + PMTiles/partitioned assets — hostable anywhere, no SaaS backend (ADR-008). This replaces the "email a zipped shapefile" workflow and is deliberately prioritized over print output. A managed sharing service is a separate, future product decision.

## Editing (decided — ADR-002 as amended)

- **1.0 — safe editing**, delivered by the first-party editing plugin (02, 12): add/move/delete features, attribute editing, undo/redo, transactions in the local mutable store (ADR-007), plus **minimal snapping** — snap to vertex/segment, configurable pixel tolerance, optional grid, live validity warning. Single-user. Scheduled last within the 1.0 phase — the analysis pillars never wait on it.
- **Topology:** lightweight local feedback (snapping, validity hints) may run synchronously or incrementally; expensive dataset-wide topology checks always run asynchronously. Repairs are consent-based — original → proposed → diff → approve (05); `ST_MakeValid` is never applied silently.
- **2.x:** shared vertices, constraints, full snapping environments, topology validation, repair tooling. **3.x:** enterprise editing (multi-user, conflict resolution, branch versioning).
- **Print composer:** post-1.0 confirmed. Escape hatch: export SVG / PDF / GeoJSON / PMTiles and finish the layout elsewhere; the static publishing bundle is the primary path (ADR-008).
