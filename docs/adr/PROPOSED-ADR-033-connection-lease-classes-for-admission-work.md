# PROPOSED ADR-033 — Connection lease classes for per-request admission work

**Status:** Proposed — **decision deliberately open; binds nothing.** Drafted 2026-09-13 by the architect agent on the custodian's brief while preregistering the "filter-and-hover polish" piece (DECISIONS-PENDING entry 87); filed on `polish/filter-and-hover` for the human's sight. Accepted only on the human's word. Number: 031 is reserved for LOD, 032 is filed; 014 stays reserved.

**Would decide:** how the engine's connection pool serves short, per-request admission work, so that a lease failure is reported as what it is.

## Context

At filing, `engine/src/pool.rs` declared two lease classes (the `LeaseClass` enum, today `:170-179`, where the third now sits); `Maintenance` is documented as *"whole-file maintenance passes — today, an index build"* with capacity 1 (today `:101-106`). Predicate admission — a short, per-request, control-plane check — was folded into that class for a good reason (`engine/src/predicate.rs`: no ad-hoc connections, nothing leaves the crate), but it is not a whole-file pass. The consequence, observed as DECISIONS-PENDING entry 87 (diagnosed 2026-09-13): concurrent `viewport_query` admissions under a row filter collide at capacity 1 and the losers are refused as binder rejections (`predicate.rs`'s own history → `skp.filter_rejected_by_binder`, whose mapping is `kernel/src/skp.rs:777-781`), which the shell then discards. The pool never blocks or queues by design (this module's header item 1, `pool.rs:53-56`; `acquire`'s own doc, `:301-303`), and ordering the stream lease against the binding's permit is reserved to ADR-014 (`pool.rs:79-85`) — this question is neither.

## Decision (the engine half has landed on `polish/engine-lease-class`, per entry 91 (a)'s ruling; Acceptance below is unchanged — this ADR stays Proposed until the human's word)

The pool now declares **three** lease classes, each its own capacity, each a **chosen ceiling under ADR-010 rule 6** — declared, not discovered or measured:

- **`LeaseClass::Stream`** — `MAX_STREAM_CONNECTIONS = 4` (`engine/src/pool.rs:99`). One streaming query. Unchanged by this ADR.
- **`LeaseClass::Maintenance`** — `MAX_MAINTENANCE_CONNECTIONS = 1` (`engine/src/pool.rs:106`). A whole-file pass — today, an index build, and `Dataset::open`'s own one-time admission work. Unchanged by this ADR.
- **`LeaseClass::Admission`** — `MAX_ADMISSION_CONNECTIONS = 4` (`engine/src/pool.rs:132`), new. Bounds the concurrent per-request predicate admissions (`engine/src/predicate.rs`'s three admission stages) one binding can present at once: the shell's declared tile-stream concurrency, `MAX_IN_FLIGHT_TILE_STREAMS = 3` (`frontends/shell/src/canvas/tileGridConstants.ts:40`), plus the baseline (non-tiled) viewport query, `1` — `3 + 1 = 4`. **This is admission-side capacity, not stream concurrency, and does not pre-empt reserved ADR-014**: it says nothing about how many *streams* a binding may run concurrently (that is `MAX_STREAM_CONNECTIONS`) or about the lease/permit release ordering ADR-014 owns (`pool.rs:79-85`, unchanged).

`MAX_PHYSICAL_CONNECTIONS` (`engine/src/pool.rs:136-137`) is re-derived as the sum of all three. `engine/src/predicate.rs`'s `AdmittedPredicate::admit` leases `Admission` instead of `Maintenance` and returns `PredicateAdmitError` — `Filter(FilterError)` for all eleven admission-content refusals, `ConnectionsExhausted { class, capacity }` for a residual lease failure. **The kernel matches on that type rather than folding it** (`kernel/src/skp.rs`'s `predicate_admit_error_of`, `:511-518`, taken by `viewport_query` at `:393`): a `Filter` keeps its `skp.filter_*` code through `filter_error_of`, and the residual routes through the *existing* `EngineError::ConnectionsExhausted` arm of `error_of` (`kernel/src/skp.rs:705-708`) to `engine.connections_exhausted` — never a binder rejection. **No new `skp.*` code and no new wire code** (SKP-V0's `engine.` + variant-name rule, `protocol/skp/SKP-V0.md:266`; ADR-021 item 8's eleven-code `skp.filter_*` list untouched). It is *not* "no wire change" in the flat sense the filing claimed: on the residual-exhaustion path the code a client sees changes from `skp.filter_rejected_by_binder` to `engine.connections_exhausted` — that change **is** the fix (DECISIONS-PENDING entry 91 (a): never a false binder refusal), and the code set itself is unchanged. Alternatives weighed and rejected, unchanged from filing: raising `MAX_MAINTENANCE_CONNECTIONS` (conflates two budgets the header split on purpose); serializing admission (breaks the never-block contract and lands in ADR-014's territory); a bounded retry inside `admit` (hides a ceiling behind a spin).

**The recorded gap is CLOSED by the commit that carries this edit.** The engine-only cut left one: `kernel/src/skp.rs`'s `build_viewport_query` was pinned to `Result<_, FilterError>`, so its `?` invoked a `From<PredicateAdmitError> for FilterError` impl that rewrote `ConnectionsExhausted` into `FilterError::RejectedByBinder`, which `filter_error_of` then put on the wire as `skp.filter_rejected_by_binder` — the very false binder refusal entry 91 (a) forbids, and (after the shell's retryable set narrowed to `engine.connections_exhausted` alone) a silent tile drop. Both gates of 2026-09-14 refused the cut on that one finding. It is now fixed at both ends: `build_viewport_query` returns `Result<ViewportQuery, PredicateAdmitError>`, the kernel matches (above), and the `From<PredicateAdmitError> for FilterError` impl is **deleted** so the fold cannot return — `engine/src/predicate.rs` says at that spot why it may not be re-added. Verified by test at both ends: `kernel/src/skp.rs`'s `a_residual_admission_lease_exhaustion_maps_to_engine_connections_exhausted_never_filter_rejected_by_binder` (the wire code and its `class`/`capacity` fields, plus the `Filter` half still taking `filter_error_of`) and `engine/tests/predicate_admission.rs`'s `a_residual_admission_lease_exhaustion_surfaces_as_connections_exhausted_never_rejected_by_binder` (the engine-side type), each with its own recorded mutation. The path stays composition-unreachable for the shipped shell at the declared ceiling (below) — what changed is that it is now *correct* when reached, not merely unreachable.

## Consequences

Four more physical connections per open dataset (`MAX_PHYSICAL_CONNECTIONS` 5 → 9; the composition fact is recorded in `kernel/README.md`); three declared ceilings under ADR-010 rule 6 instead of two; no new SKP code and no new field — the residual takes a code SKP-V0 already declares; ADR-021's eleven-code list untouched; the entry-87 refusal is truthful at the engine's own type boundary **and on the wire**, and at the declared size the residual path is unreachable in composition for the shipped shell (three tile streams plus one baseline). Raw material for ADR-014 either way — the finding is appended to `pool.rs`'s existing note rather than cited as evidence for anything else.

## Acceptance

On the human's word, after the polish piece's engine half lands with its tests (the concurrent-admission test; the lease-failure-surfaces-as-`ConnectionsExhausted` test) and the architect gate affirms it.
