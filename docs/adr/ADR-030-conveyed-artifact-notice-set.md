# ADR-030 — The notice set a conveyed artifact must carry

**Status:** Proposed — filed 2026-09-08 on the human's ruling (DECISIONS-PENDING entry 57: *"ADR-030
filed Proposed with (a) as decision on item 9's landing"*). Candidate (a) below is the decision the
human has named; it becomes Accepted, on the human's word, when the release cut's item 9 (both notice
generators) lands and its gates confirm the property. Until then this ADR binds nothing beyond
recording the question. Drafted from the architect's skeleton at the packaged-build re-check
(`RELEASE-0.1.md` Amendments 4–6).

**Related:** ADR-009 (license layers; item 7 is bundle-scoped — the viewer's notice; item 1 the core),
ADR-017 Corrigendum 3 (`viewer_license` — the distributed code's notice and corresponding-source
route), `DEPENDENCY-LICENSES.md` (the repository dependency audit and the EPSG/IOGP data-terms
record), `PRE-PUBLIC-CHECKLIST.md` item 4, `renderer/bundle-viewer/notice.mjs` (the one-source
generator), docs/01 principles 3 and 8, docs/14.

## Context

ADR-009 item 7 says what a *published bundle* distributes (the AGPL viewer) and Corrigendum 3 of
ADR-017 gives the bundle a `viewer_license` member; ADR-009 item 1 sets the core's license layer; the
pre-public checklist's item 4 audits the *repository's* dependency tree. Nothing decides what a
**conveyed artifact** — an installer, a bundle — must enumerate, in what form, generated from what,
or whether an artifact may ship with a gap that is *named* rather than closed.

In the absence of a rule the record decided per artifact and per amendment: the bundle viewer's
notice was generated from its own esbuild metafile (one source, byte-identity tested); the packaged
app's `NOTICE.txt` was then generated by calling the same function from the shell's working
directory, which silently attributed the *shell's* `node_modules` versions to the viewer and dropped
Arrow's retained NOTICE — caught at a gate, fixed by resolving paths from the generator's own tree.
The corrected file then still claimed, in its header, to cover "the viewer and the packaged
frontend" while enumerating neither the packaged frontend's own npm set (React, deck.gl, the shell's
apache-arrow) nor the Rust crates statically linked into the binary. Each was a true sentence about
one artifact that became false about another, in a shipped legal file — the failure shape
`notice.mjs`'s own doc comment names as the worst available for a notice.

## The decision (candidates; (a) named by the human, accepted on item 9's landing)

- **(a) Every conveyed artifact enumerates every third-party work it actually carries, generated
  from that artifact's own build manifest — no artifact ships with a named gap.** For the packaged
  shell app: the viewer's esbuild metafile, the shell's Vite build manifest, and the Rust lockfiles
  (the shell crate's and the workspace's statically linked crates), each read from its own tree, into
  one `NOTICE.txt` whose scope sentence is mechanically tested against the artifact. For a published
  bundle: the viewer's metafile, as today.
- **(b) Named-gap shipping is permitted**, but only where the gap is enumerated by set, named in the
  artifact's own notice, in `DEPENDENCY-LICENSES.md`, and in the release's KNOWN-LIMITATIONS, with a
  due milestone.
- **(c) Status quo** — per-artifact rulings, which the record above shows failing.

The human's ruling names **(a)**; the release cut's item 9 builds it; **(b)** is the interim the
same ruling authorised for PR #31 only until item 9 lands (the two gaps named in the notice itself),
and it expires with item 9.

## Consequences (of (a))

- The shell's Vite build needs a manifest-driven notice generator and the Rust set a lockfile-driven
  one, both without adding a dependency (a node script over the lockfile and the cargo registry; a
  tool such as `cargo about` would be a dependency-tree addition and is not licensed by this ADR).
- Every notice's scope sentence becomes a tested property, one level above
  `noticeByteIdentity.test.ts`: the artifact's notice enumerates exactly the manifest's packages
  and the lockfile's crates.
- The "one source, cannot drift" property already built for the viewer generalises rather than
  being re-argued per artifact.
- Nothing here changes ADR-009's layers, ADR-017's bundle format, or the EPSG/IOGP data-terms
  record; the IOGP acknowledgement and terms URL stay in every conveyed notice.

## Reopen condition

A new conveyance channel (a macOS/Linux artifact; an SDK package under ADR-009's Apache-2.0 layer;
a plugin distribution) reopens this ADR for that channel's manifest source rather than inheriting
(a) by assumption.
