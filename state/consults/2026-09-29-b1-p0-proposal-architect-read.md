**Verdict: block** (fix before it goes to Fable). Reviewed: main @ 4e46166. The draft files are untracked in the working tree and not committed anywhere.

1. BLOCKING, §6, the claim that ADR-021 "anticipates" a twelfth code. The quoted phrase does not match its source byte for byte. It drops "it is" and "into this list by name", with no ellipsis. It also misreads the sentence. Paraphrase: the sentence is the exhaustive-mapping discipline: any new failure mode fails the build until it is mapped into the eleven named codes. It does not invite a twelfth code. The code reads it the same way (`FilterError` and `PredicateAdmitError` docs: a twelfth code would invent wire taxonomy). The ADR-021 Note 2026-09-24, item 2, says the eleven codes stand. 6a is still the human's to choose. The draft should say it changes Decision 8, not that Decision 8 foresaw it.
2. BLOCKING, §6b, "ADR-021 defines that code as a node the allowlist does not name." It does not. Decision 8 and SKP-V0 §7.5 give only the code name and its field. That definition is in the doc comment on `FilterError::ConstructNotAdmitted` in predicate.rs. The code also already uses the code for named nodes in shapes it does not admit (`walk_expr`: IN with a non-literal member, LIKE with a non-literal pattern, NOT/IS NULL with the wrong operand count; `differential_operands`: sentinel mismatch). So "a comparison node is named" does not settle it.
3. BLOCKING, §3 rule 6 and §10.1, "as H5 and round 17 item 3 relied on." H5 (B1 prereg §5, and Amendment 2's result) covers only a REAL column against a decimal literal. Rule 6 also admits integer literals (`f32 = 16777217` matches a stored 16777216) and large literals rounded into DOUBLE. Neither H5 nor round 17 covers those. Present that part as new policy, not inherited reliance.
4. NOTE: rule 6's stated mechanism ("the literal is converted to the column's own type") is wrong for REAL against a double literal. There the column widens to DOUBLE, per the §2.2 table and matrices.txt (row dbl, column f32 = W). The admission outcome is unchanged.
5. NOTE, §2.3: "The bare column is refused … with not_boolean" is true only for a non-BOOLEAN column. `bind_admit` admits a bare BOOLEAN column.
6. NOTE, §6b: the quote of Fable's A2-1 test lowercases the source's opening "An". Mark it verbatim with the capital, or label it paraphrase.
7. NOTE, §2.2 DECIMAL table: only scales 1, 9, 18, 19, 20, 27, 28, 29, 34 and 36 were probed. "Fails at the first scale where digits+s > 38" is inferred between those points (for example, TINYINT at 35 was never run).
8. NOTE, header "every number comes from that run": the counts (7,620 / 6,804 / 1,676 / 576 / 91 / 8 / 1,001 / 363 / 30) are not in matrices.txt, and the probe was deleted. Keep the artifact that carries them.
9. NOTE, §4 "types that same tree": `structural_admit` returns only column names and drops the parsed tree. The fix has to change what stage 1 returns, or parse again. Say which.
10. §7 completeness. The ADR-021 changes are correctly classed as the human's typed text: the 6.3 Note, the Decision 8 code, and the arithmetic narrowing. One location is wrong: the arithmetic set is in ADR-021's Consequences and "What this ADR does not decide" ("fixed by this ADR"), not in the Decision. Fable's paragraph keys on Decision text, so name the location. It is still the human's, because ADR-021 is accepted and immutable. Missing from the list: SKP-V0 §7.4, whose admitted list names `+ - * /`, needs rewording under 5a. Also missing: whether 5a or 6b alone, with no new code, needs a version bump (ADR-021 Decision 2's bump-only evolution rule). No change needed: ADR-023 §2 (the type list is untouched), ADR-004 (the refusal stays on the control plane), docs/08 (no row; make no perf claim). §21a full gating is correct.
11. Q3 (principle 8). Refusing on failure or stored-value change is consistent with docs/01 principle 8. Rule 6 is defensible only if the 6.3 Note names literal rounding into the column's type as a declared, admitted conversion, with E-20 as its pin. The proposed Note text leaves it out, so it would be admitted by omission, which principle 8 weighs against. Fable's expectation ("change the comparison" is refused) plausibly covers `f32 = 16777217`, so put that case to Fable by name.
12. NOTE, §3 rule 4, "pairwise checks sound for mixed IN/BETWEEN": this is untested for the binder's n-ary common type. Only `(1, 1.5)` and `1 AND 1.5` were probed. A list such as `i64 IN (<HUGEINT literal>, 0.5)` may fall back to DOUBLE and round the column. It needs a discriminator.
13. Q4. Rejecting 6b is right, but the sound reason is different. Paraphrase: `ConstructNotAdmitted`'s Display text says the construct is off the allowlist, a docs/09 security boundary. For a type refusal that engine message states a false fact, and principle 8 plus Fable's A2-1 test both reject a false code. Drop the "ADR-021 defines" argument (finding 2).
