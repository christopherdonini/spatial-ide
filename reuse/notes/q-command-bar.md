### 3.1 `@codemirror/autocomplete` — `FuzzyMatcher` and the completion-context model (best port target for matching and `@`)

- **Repo / commit.** GitHub mirror `codemirror/autocomplete` @ `9a01794` (2026-04-15; README: "This repository has moved to https://code.haverbeke.berlin/codemirror/autocomplete"). Published `@codemirror/autocomplete` 6.20.3 (npm, 2026-06-03) read from its tarball: `dist/index.js` carries the same penalties and the same `Math.min(word.length, 200)` cap and the same `chars.length == 2 ? null` rule (`dist/index.js:276`, `:297`, `:337`).
- **Licence.** MIT — `LICENSE` "Copyright (C) 2018-2021 by Marijn Haverbeke … and others"; same text in the npm tarball. Green.
- **Activity.** 87 changelog sections; 6.20.1 dated 2026-03-02, 6.20.3 published 2026-06-03. Tests: `test/webtest-autocomplete.ts`. CI not visible on the mirror.
- **Why it matters.** It is the smallest matcher that ranks the way a command list wants (prefix > by-word initials > substring > scattered), returns highlight ranges, and is ~130 lines with one import (`codePointAt`/`codePointSize`/`fromCodePoint` from `@codemirror/state`, trivially replaced by `String.prototype.codePointAt`). Its `CompletionResult` also models exactly what `@field` needs: a completion **range** inside a larger text.
- **How it works.**
  - `src/filter.ts:5-11` — penalties: `Gap -1100`, `NotStart -700`, `CaseFold -200`, `ByWord -100`, `NotFull -100`; 0 is a perfect match.
  - `:58-139` `FuzzyMatcher.match(word)`: single-char patterns match only at the start (`:62-68`); exact prefix → 0 or `NotFull` (`:70-71`); otherwise one left-to-right scan (capped at 200 chars) tracks four candidate alignments at once — precise, case-folded adjacent, by-word (each pattern char at a word start, camelCase aware), and any-order-preserving — then returns the best in a fixed preference order (`:120-134`). Two-character patterns refuse scattered matches (`:133`). Score subtracts word length, so shorter labels win ties.
  - `src/state.ts:18-79` `sortOptions`: score + `option.boost`, optional `section` with numeric or `"dynamic"` rank, comparator fallback, de-duplication. `boost` is the hook a recency boost would use.
  - `src/completion.ts:220-246` `CompletionResult { from, to?, options, validFor?, filter? }` — the source returns options for the text between `from` and `to`; `validFor` lets the list re-filter synchronously while the user keeps typing inside the same token. `:104-108` `explicit` distinguishes a requested completion from an automatic one; `:129` `matchBefore(regexp)`.
  - ARIA: `src/state.ts:187-198` sets `aria-autocomplete="list"`, `aria-haspopup="listbox"`, `aria-controls`, and `aria-activedescendant` only when an option is selected; `src/tooltip.ts:265-289` `role="listbox"`, `role="option"`, `aria-selected`.
  - Keys: `src/index.ts:40-50` default keymap is Ctrl-Space/Escape/Arrow/PageUp/PageDown/**Enter** accept. **Tab is not bound by default** — consistent with Batch 10's correction that Tab-to-complete is Spatial IDE's own choice.
- **Reuse.** Port `FuzzyMatcher` (~130 lines) and the `{from, to, options, validFor}` shape as the `@` completion contract. Do not take the package: it drags `@codemirror/view`, `state`, `language`, `@lezer/common` (npm `dependencies`), i.e. an editor.
- **Not to reuse.** The tooltip DOM, the CodeMirror state facets, snippets, closebrackets.
- **Licence implications.** MIT into AGPL-3.0-or-later: compatible; the copyright and permission notice must travel with the ported file (file header plus a notice entry — see §4 for the missing notice route).
- **Reuse mode: PORT.** Avoided work: small. Recommendation: port `FuzzyMatcher` as the one matcher for `/` commands, plain search, `?` help and `@` fields. Timing: in milestone 3's form, before code.

  - Filter and sort: `cmdk/src/index.tsx:361-412` — score every item; sort **DOM nodes** by score with `appendChild`, then groups by max item score. ARCHITECTURE.md: "The DOM is authoritative … every item and group [stays] rendered in the React tree".
  - **No recency** anywhere in `cmdk/src` (grep for recent/history/MRU empty).
  - Keys: `:579-640` — ArrowUp/Down, Home/End, Enter dispatches a custom `cmdk-item-select` event; Ctrl+N/J/P/K vim bindings default **on** (`vimBindings = true`, `:200`); IME guarded by `isComposing || keyCode === 229` (`:586`, commit `f34d463`). No Tab handling.

Avoided work: small. Timing: now (decision input for the milestone-3 form).

- **Synthesis.** Nobody round-trips arbitrary text into pills. ### 3.8 W3C APG combobox — what a conforming bar must do (fetched 2026-10-08)

From https://www.w3.org/WAI/ARIA/apg/patterns/combobox/ and its "list autocomplete" example:
- The input has `role="combobox"`, is in the Tab sequence, and keeps **DOM focus** while a listbox option is active; the active option is referenced by `aria-activedescendant` and carries `aria-selected="true"`.
- `aria-expanded` is `false` when the popup is hidden and `true` when shown (cmdk hard-wires `true`); `aria-controls` names the popup ("only needs to be set when the popup is visible"); `aria-autocomplete` is `list` for this behaviour; `aria-haspopup` is implicit `listbox`.
- Labelled by a visible `<label>` or `aria-label`. Popup, popup indicator and descendants are **excluded from the Tab sequence**.
- Keys: Down/Up move into or through the list; Enter accepts the selected suggestion; Escape closes the popup (optionally clears when already closed); Alt+Down opens without moving focus; printable characters type into the box. **Tab has no defined acceptance behaviour** in the pattern or the example — confirming the project's own Batch 10 correction (`state/drafts/design/RESEARCH-BATCHES-08-10.md:303 @ 4561f3b8`): Tab-to-complete is a Spatial IDE design decision to test, not conformance.
- The example warns "There may be support gaps in some browser and assistive technology combinations" and that testing with assistive technologies "is essential before considering use in production systems".
- Implication for acceptance: a test list can be derived mechanically from these items (role, expanded true/false, activedescendant only when an option is active, aria-selected on that option, popup out of Tab order, Escape closes and keeps text, Enter on an active option accepts, Tab leaves the bar or completes per the human's ruling, IME composition never triggers accept/run). The milestone-1 registry already ignores `isComposing` (`SHELL-MIGRATION-MILESTONE-1-PREREGISTRATION.md`, §(c)); cmdk and kbar show the same guard (`cmdk/src/index.tsx:586`, `kbar/src/KBarResults.tsx:48`).

## 4. Do not reinvent / worth owning

**Do not reinvent**
- *Spatial IDE should not implement a fuzzy matcher from scratch because `@codemirror/autocomplete`'s `FuzzyMatcher` already provides prefix/by-word/substring/scattered ranking with highlight ranges in ~130 lines under MIT, unless requirement R — searching thousands of items (`#` feature search) — later invalidates that, in which case evaluate uFuzzy (MIT, zero-dependency) as a dependency.*
- *Spatial IDE should not implement native menus with a new library because `@tauri-apps/api` 2.x (already a dependency, Apache-2.0 OR MIT) provides `Menu`, `MenuItem` with `accelerator: 'CmdOrCtrl+…'`, and `setAsAppMenu()`, and the shell's `core:default` capability already includes `core:menu:default`, unless a Linux/Windows window menu is later wanted (then `setAsWindowMenu`, same API).*
- *Spatial IDE should not invent its combobox semantics because the W3C APG combobox pattern specifies role, states, focus and keys, unless the human rules a Tab behaviour the pattern does not define (then it is a declared, tested extension).*

**Worth owning (build), and what each still borrows**
- **The palette component** (one React component + plain CSS, no dialog library): borrows APG's attribute set and key table, cmdk's IME guard, VS Code's live result count and "show `aria-activedescendant` only when an option is active".
- **The registry entry shape** (extend milestone 1's `layout/actionRegistry.ts`): borrows VS Code's `registerAction2` fan-out (one entry → palette row, shortcut, macOS menu item), its `when` (hidden) vs `precondition` (disabled) split, Lumino's `isEnabled/isVisible/isToggled`. Not a `when`-expression engine (Batch 10 review, `:306`).
- **Ranking** = ported `FuzzyMatcher` score, then a recency rule borrowed from Zed (used-before pinned above unused, most recent first) or VS Code (MRU then alphabetical). Where recency is stored is B2's preferences question (§10.6), so the first cut can rank without it.
- **`/filter` drafting** (narrow internal form): borrows TipTap's trigger rule for `@` and CodeMirror's `{from, to, options, validFor}` completion range, with an `AbortSignal`-style generation check so a stale completion never applies.
- **Clause cards**: borrows Kibana's structured pill (`disabled`, `negate`, label) and "disabled pills are dropped before composition"; Metabase's "recognise only an exact shape, else keep whole as an expression"; Superset's verbatim rule. Concretely: a card holds the user's **text verbatim** plus its enabled flag; the predicate sent is the enabled cards' texts each wrapped in one paren pair and joined with ` AND ` — a mechanical join of verbatim texts, not a rewrite; zero enabled cards → `filter: null` (today's `predicateTextToFilter`). Whether a card is "simple" (field/op/value chips) or "advanced" is a display decision from an exact-shape recogniser over the user's text; anything it does not fully recognise renders as one advanced card with the text unchanged. The kernel admits or refuses the joined predicate; a refusal keeps the previous applied filter (today's `FilterPanel` behaviour). Note: refusals then point at the joined text, not a card — the form should decide whether to show which card a refusal's `column`/`construct` field names.
- **Notice route for ported code** (gap found): `generateNotice.mjs` enumerates only build manifests and DuckDB's tree; a ported MIT file under `frontends/shell/src/` would be **missing from the shipped NOTICE**. Before any PORT, the human/architect needs a fifth notice set (e.g. hash-pinned texts under `LICENSES/third-party/<work>/` plus an SPDX header on the ported file, mirroring the DuckDB route). Alternatively write the matcher fresh from the published algorithm description (CONCEPTUAL DONOR), which needs no notice — counsel's call which is cleaner.

**Build versus adopt, under the no-new-dependency rule.** Build. Nothing here requires a dependency: the palette is one APG combobox; the matcher is a ~130-line port (or a fresh write); native menus come from the Tauri API the shell already has; cards are a list of `{text, enabled}` with a join. The only dependency that would buy real work is `cmdk` (~26 packages incl. Radix, ~1 MB), and its defaults (modal focus trap in `Command.Dialog`, Ctrl+K vim binding, `aria-expanded` always true, DOM-sorted compound items) work against three of the milestone's acceptance items. No candidate offers filter cards at all. If the human prefers a dependency anyway, the least-cost one is `@leeoniya/ufuzzy` (MIT, zero deps, 8.5 KB min) for matching only — but it is not needed at command-list scale.
